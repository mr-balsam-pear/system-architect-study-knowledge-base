# 系统架构师知识库多工作区“夜航指挥台”设计规格

日期：2026-08-12  
状态：已完成对话确认，待用户审阅书面规格

## 1. 目标

将当前所有学习功能连续渲染在同一长页面的结构，重构为“精简指挥台首页 + 独立工作区 + 短任务弹窗”的单应用界面。新结构必须降低首屏与 DOM 复杂度，使学习者能快速判断下一步行动，同时完整保留知识点、题库、真题、训练、播客和学习档案的既有业务能力。

视觉方向采用“A · 夜航指挥台”：深墨背景、琥珀行动信号、紫色辅助层。布局应具备清晰的编辑式层级和应用感，避免均匀卡片墙、信息堆叠及装饰性统计。

## 2. 设计原则

1. 先行动，后统计：今日主行动是首页视觉中心，数据摘要退居辅助层。
2. 一页一任务域：知识阅读、答题、真题、训练、播客和档案分别进入独立工作区。
3. 短任务用弹窗：记录、确认等上下文明确的短流程不占用独立页面。
4. 长内容用路由：PDF、知识正文、题库和档案不可塞入小弹窗。
5. 应用内保持状态：路由切换不清空筛选、阅读位置、答题进度或播客状态。
6. 双主题同构：白天与黑夜仅改变设计令牌，不改变信息结构和操作位置。

## 3. 总体架构

采用单壳 Hash SPA。桌面端使用左侧常驻侧栏，主内容区按路由渲染一个工作区；移动端侧栏折叠为顶部“工作区”导航抽屉。

### 3.1 路由

- `#/today`：精简今日指挥台
- `#/knowledge`：知识点阅读器
- `#/practice`：互动题库
- `#/questions`：本机真题索引
- `#/questions/:id`：真题详情
- `#/training`：训练中心
- `#/podcasts`：章节播客
- `#/records`：学习档案

访问空 Hash 或未知路由时回退到 `#/today`。刷新、浏览器前进和后退必须恢复路由对应的工作区。

### 3.2 应用壳

桌面端应用壳由三部分组成：

- 左侧侧栏：品牌、七个工作区入口、主题切换、本机服务状态。
- 主内容区：仅渲染当前工作区。
- 跨工作区层：迷你播客播放器、全局记录弹窗、移动端抽屉。

移动端将侧栏替换为顶部栏和全高导航抽屉。抽屉关闭后焦点返回触发按钮。

## 4. 今日指挥台

首页采用精简结构，不再承载完整学习闭环仪表盘。

### 4.1 内容层级

1. 考试倒计时与日期。
2. 一句冲刺目标：“今天只完成一个得分闭环。”
3. 单一“下一步行动”，优先级依次为：到期复习、继续未完成训练、开始限时训练、记录判断规则。
4. 两个次级入口：最近学习、最近播客。
5. 三项轻量摘要：到期复习数、可学习知识点数、可收听节目数。

首页不展示完整的近期记录、薄弱专题列表或论文素材列表；这些内容合并进学习档案。

### 4.2 视觉语言

- 深墨色页面作为默认夜间主题画布。
- 琥珀色仅用于主行动、选中导航、倒计时和关键焦点，单视口覆盖不超过约 5%。
- 紫色只用于任务编号、播客和辅助状态。
- 使用非等权布局，主行动显著大于次入口与数据摘要。
- 禁止渐变文字、玻璃拟态、均匀统计卡片墙和无语义装饰圆。

## 5. 独立工作区

### 5.1 知识点阅读器

- 桌面端：章节树与正文双栏，搜索位于工作区顶部。
- 移动端：正文为主，章节树进入抽屉。
- 保留知识搜索、章节定位、前后知识点、教材来源、关联播客和记录学习能力。
- 离开再返回时恢复当前知识点、章节树展开状态、搜索词和正文滚动位置。

### 5.2 互动题库

- 由题目导航、答题区和答题卡组成清晰的分区布局。
- 单题模式保持沉浸阅读；整卷模式进入独立的沉浸答题视图。
- 桌面端筛选器位于工作区标题下；移动端收进筛选抽屉。
- 保留即时判分、主观题自评、整卷交卷、只读复盘、限时和知识点联动。
- 路由切换后恢复当前题目、答案、计时、答题卡和筛选条件。

### 5.3 本机真题索引

- 索引页仅负责筛选、结果数量和题目列表。
- 点击题目进入 `#/questions/:id`，不再打开 PDF 预览弹窗。
- 列表项突出年份、科目、题型和标题，版权与版本提示为辅助信息。

### 5.4 真题详情

- 桌面端使用双栏：左侧 PDF，右侧题目信息、关联知识点与记录入口。
- 移动端上下排列，并提供固定但不遮挡正文的操作区。
- PDF 不可用时保留关联知识点与记录能力，并提供明确回退提示。
- 浏览器返回应回到之前的真题索引筛选与滚动位置。

### 5.5 训练中心

- 采用三条非等权训练路径：案例分析、论文写作、模拟与机考。
- 当前推荐路径占据主要版面，其余路径为次级入口。
- 资料台账作为辅助链接，不再与训练路径等权展示。
- 案例复盘与论文素材记录打开对应弹窗。

### 5.6 章节播客

- 桌面端采用节目库与播放器双栏；移动端上下排列。
- 保留仅显示未听完、不可用章节状态、播放进度、知识点联动和记录入口。
- 迷你播放器跨工作区存在，Hash 路由切换不得中断音频或重置播放进度。
- 第 1、4 章保持无播放控件的不可用状态；其余节目按现有数据展示。

### 5.7 学习档案

合并原学习闭环仪表盘，承载：

- 今日到期复习
- 近期学习记录
- 薄弱专题
- 论文素材
- 档案追加入口

学习档案继续以本机 Markdown 为唯一持久化来源，不覆盖用户手工内容。

## 6. 弹窗与抽屉

### 6.1 使用弹窗的流程

- 记录知识点学习或错题
- 记录案例复盘
- 记录论文素材
- 播客收听复盘
- 未保存记录的关闭确认

桌面端使用居中弹窗；移动端使用全高或接近全高的底部面板。长篇 PDF 和工作区筛选不使用居中弹窗。

### 6.2 筛选抽屉

题库与真题在移动端将筛选器收进抽屉。已启用筛选条件需要在工作区顶部显示精简摘要和清除入口。

### 6.3 无障碍行为

- 打开弹窗或抽屉后锁定背景滚动。
- 焦点进入容器，`Esc` 关闭，关闭后返回触发元素。
- 提交期间禁用重复提交。
- 所有焦点环达到至少 3:1 对比度。

## 7. 状态与数据流

### 7.1 路由状态

路由层监听 `hashchange`，解析目标工作区和可选实体 ID。工作区首次进入时初始化，之后复用内存状态。未激活工作区不应持续占据主内容 DOM。

### 7.2 需要保持的状态

- 主题选择
- 当前知识点、搜索词、章节树展开和阅读位置
- 题库筛选、当前题目、答案、计时和整卷状态
- 真题筛选及列表滚动位置
- 播客当前节目、播放位置、完成状态和过滤条件
- 学习档案筛选或当前上下文

已有本地存储策略保持兼容；无须为本次视觉重构改变业务数据格式。

### 7.3 按需渲染

共享数据可在应用启动后加载一次。具体工作区 DOM 在首次打开时创建；切换时卸载视图或缓存纯状态，不把所有工作区同时插入页面。跨工作区的音频元素和弹窗根节点留在应用壳。

## 8. 加载、空状态与异常

- 工作区加载使用局部骨架，不使用全屏遮罩。
- 空状态必须给出下一步行动，例如“今天没有到期复习 → 开始限时训练”。
- API 失败时保留页面框架，显示人类可读说明、重试按钮和本机服务状态。
- 不直接展示堆栈、内部路径或技术异常文本。
- PDF 加载失败不影响查看关联知识点和追加学习记录。
- 未保存表单关闭时确认；筛选变化和普通路由切换不弹确认。

## 9. 响应式与视觉验收

必须验收 320、375、414、768 和 1280px：

- `html` 与 `body` 使用 `overflow-x: clip`，不存在横向页面滚动。
- 可点击文字保持单行；侧栏导航在移动端进入抽屉。
- 标题支持长词换行，网格轨道使用 `minmax(0, 1fr)`。
- 迷你播放器不遮挡最后一行内容或主要操作。
- 弹窗、抽屉和真题详情在窄屏可完整操作。
- 白天与黑夜主题保持相同层级、布局和焦点顺序。
- 动效只改变 `transform` 与 `opacity`，并支持 `prefers-reduced-motion`。

## 10. 兼容与范围边界

必须保留：

- 现有知识点、题库、真题、播客和学习档案数据及接口。
- 学习记录追加语义和 Markdown 持久化规则。
- 当前题库判分、整卷、复盘、播客播放和知识关联逻辑。
- 浅色/深色主题持久化。

本次不包含：

- 修改学习内容、题目答案或教材数据。
- 引入账号体系、云同步或新的后端框架。
- 删除旧业务功能。
- 更换现有本机数据格式。

允许为实现清晰边界而拆分前端文件，但不得删除生产数据或破坏现有接口。

## 11. 测试与完成标准

### 11.1 自动化

- 所有现有 Python 单元测试通过。
- 题库、播客、主题和布局 Node 测试通过。
- 新增路由测试，覆盖默认路由、未知路由、详情路由及前进/后退。
- 新增工作区契约测试，确保首页不同时包含所有功能 DOM。
- 新增状态保持测试，覆盖题库、知识点和播客跨路由行为。
- 所有 JavaScript 文件通过语法检查。

### 11.2 浏览器验收

- 逐一访问八个路由和真题详情路由。
- 主题切换并刷新后保持。
- 知识、题库和真题返回后恢复上下文。
- 播客跨路由持续播放。
- 桌面弹窗与移动抽屉焦点正确。
- 320/375/414/768/1280px 无横向溢出和控件遮挡。
- 控制台无应用代码错误。

### 11.3 Hallmark 验收

- 使用 Workbench 应用族和“夜航指挥台”统一设计系统。
- 全部颜色、字体、间距、字号、圆角和动效引用设计令牌。
- 通过 Hallmark 58 项反模板审计。
- 页面不形成均匀卡片墙，不使用无语义装饰、渐变文字或玻璃拟态。

## 12. 预期文件策略

实施计划可在审阅阶段决定精确文件名，设计允许：

- 保留 `site/index.html` 作为应用壳。
- 保留 `site/tokens.css` 作为双主题令牌源。
- 调整 `site/styles.css` 为应用壳和共享组件样式，并按需要拆分工作区样式文件。
- 将 `site/app.js` 的路由、工作区视图和业务编排按职责拆分为独立模块。
- 复用 `practice-state.js` 与 `podcast-state.js` 的纯状态逻辑。
- 新增路由、视图和状态保持测试。

任何生产文件删除都不属于默认实施方案；如后续计划确需删除，必须在计划中逐项列明并另行确认。
