# 播客迷你播放器紧凑布局设计

## 目标

修复章节播客迷你播放器在中等宽度页面中横向铺满、按钮过重、整体高度偏大的排版问题，使其呈现为紧凑的底部工具条，同时保留播放与节目库入口。

## 根因

播放器当前仅在 `max-width: 30rem` 时进入移动布局。在宽度高于 480px、但可用画布仍有限的场景中，它继续使用最大 `42rem` 的三列桌面布局；标题、状态和两个高权重按钮共同占据较大面积，造成截图中的比例失衡。

## 设计

- 桌面宽屏维持右下角悬浮位置，但最大宽度收敛，视觉上更接近工具条而不是内容卡片。
- 新增中等宽度适配区间：内容区使用 `minmax(0, 1fr) auto auto`，标题与状态允许省略，不换行。
- 标题使用 `--text-sm`，状态使用 `--text-xs`，形成清晰的两级信息层级。
- 播放按钮保持主要操作，但统一为紧凑高度；节目库入口降低背景和边框权重，作为次要文字操作。
- 480px 以下继续隐藏节目库入口，保留标题、状态与播放按钮，并贴合页面底部。
- 保留现有播放器 DOM、播放状态、跨路由播放和按钮文案，不修改 JavaScript 数据流。

## 交互与无障碍

- 播放按钮与节目库入口保持单行文本。
- 保留可见的 `:focus-visible`、`:active`、`:disabled` 状态。
- 不增加布局属性动画；仅允许已有的颜色或位移反馈。
- 组件不得产生横向滚动，标题过长时使用省略号。

## 修改范围

- 修改：`系统架构师知识库/site/styles/overlays.css`
- 修改：`系统架构师知识库/tests/test_command_center_layout.js` 或现有最贴近播放器的布局契约测试
- 不修改播放器 JavaScript、路由、音频状态与内容数据。

## 验收标准

- 截图对应的中等宽度下，播放器不再横向铺满画面，整体高度明显收紧。
- 标题、状态、播放按钮和节目库入口均不换行、不重叠。
- 320px、375px、414px、768px 与 1280px 下无横向滚动。
- 480px 以下节目库入口隐藏，播放按钮保持可用。
- 相关 Node 测试、CSS 静态检查和 `git diff --check` 通过。
