# 论文项目素材库模板

论文 4 选 1，120 分钟，**≥ 2500 字**。决定成败的不是写作技巧，
而是你**手上有没有 2–3 个能说清楚的真实项目**。

## 铁律

- 只能写自己**真实参与**的项目。虚构项目在「角色、决策、数据、反思」四个追问下必然崩塌。
- 项目不必高大上，但必须能回答：**你做了什么决策、为什么这么定、结果如何证明**。
- 准备 **3 个项目**，覆盖不同主题，才能应对不同命题方向。

## 项目卡片（每个项目填一张）

```markdown
## 项目 A：<项目名>

### 基本信息
- 时间跨度：____ 至 ____
- 我的角色：<架构师 / 技术负责人 / 核心开发>
- 团队规模：__ 人
- 系统规模：用户 __ 万 / 日活 __ / 峰值 QPS __ / 数据量 __ TB
- 业务目标：（一句话说清解决什么问题）

### 技术栈与总体结构
- 架构风格：
- 关键技术：
- 部署形态：

### 关键决策 1
- **背景/约束**：
- **可选方案**：① ② ③
- **我的决策**：选了 __
- **决策理由**：（技术 + 非技术因素）
- **代价/风险**：
- **结果**：<量化数据，如 P99 从 800ms 降到 120ms>

### 关键决策 2（同上）

### 关键决策 3（同上）

### 遇到的真实问题与解决
1. 问题 → 定位 → 措施 → 结果

### 可迁移的反思
- 如果重做，会改变什么？
- 这个项目让我对哪个架构原则有了新的理解？
```

## 三个项目的主题搭配建议

| 项目 | 建议侧重 | 适合应对的命题方向 |
|---|---|---|
| A | 高并发 / 性能 | 性能优化、缓存、负载均衡、微服务拆分 |
| B | 数据 / 集成 | 数据架构、大数据处理、系统集成、SOA |
| C | 安全 / 可靠性 | 安全架构、容灾、可靠性设计、演化维护 |

若你的项目经历集中在某一类，可用**同一项目的不同侧面**充当不同主题，
但决策与数据不能重复。

## 论文提纲练习（15 分钟/个）

```markdown
## 提纲：<命题>

**选用的项目**：项目 A（理由：命题要求 ___，本项目有 ___）

### 摘要（300–400 字）
- 项目背景（1 句）：
- 我的角色与职责（1 句）：
- 关键技术决策（2–3 句）：
- 成效（1 句，带数据）：

### 正文结构
1. 项目背景与我的职责（300 字）
   - 业务目标、规模、时间、我的角色
2. 技术选型与总体架构（400 字）
   - 总体结构 + 为什么是这个结构
3. 关键决策与实施（1000 字，主体）
   - 决策 1：背景 → 方案比较 → 选择 → 实施 → 效果
   - 决策 2、3 同上，每项约 300 字
4. 实施中的问题与应对（400 字）
   - 真实问题 + 解决 + 学到了什么
5. 成效与反思（300 字）
   - 量化结果 + 不足 + 改进方向

### 预计字数：____ 字
```

## 常见失分点

| 问题 | 表现 | 修正 |
|---|---|---|
| 跑题 | 题目问云原生，通篇讲微服务框架安装 | 首段回扣命题关键词 |
| 空泛 | 大量教材定义，没有项目细节 | 每讲一个概念，立刻接项目事实 |
| 角色不清 | 只说「我们」，看不出本人贡献 | 明确「我负责…」「我决定…」 |
| 无数据 | 只有「性能提升明显」 | 写具体数字与对比基线 |
| 结构失衡 | 背景写 800 字，核心决策只有 300 字 | 决策部分占正文 50% 以上 |
| 技术错误 | 概念用错（如把 CAP 说成三选二必选二） | 写完自查术语 |

## 每周训练安排

- **周五**：写 1 个提纲（15 分钟）+ 素材卡补充（30 分钟）
- **周日**：完整限时论文（每两周 1 篇）

限时标准：**100 分钟写正文 + 15 分钟摘要 + 5 分钟检查**。
摘要最后写，但必须写在答题纸对应位置。
