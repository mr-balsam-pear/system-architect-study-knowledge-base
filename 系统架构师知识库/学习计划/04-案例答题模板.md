# 案例分析答题模板

案例分析共 5 题，**第 1 题必答 + 后 4 题选 2**，共答 3 题，90 分钟。
平均每题 30 分钟：读题 5 分钟、列要点 5 分钟、书写 18 分钟、检查 2 分钟。

## 第一步：拆解题干（5 分钟）

读题时用笔标出四类信息，不要一边读一边想答案：

| 标记 | 内容 | 作用 |
|---|---|---|
| **业务目标** | 系统要解决什么问题 | 决定答题不能脱离场景 |
| **约束** | 规模、时间、成本、合规、既有系统 | 约束往往就是得分点 |
| **现状** | 已有架构、痛点 | 决定「改进」而不是「重做」 |
| **动作词** | 分析/设计/指出/说明/比较 | 决定答题形式 |

**动作词对应答法**：

- 「指出问题」→ 分条列问题，每条一句，不要展开措施；
- 「说明原因」→ 因果关系，止于原因；
- 「给出措施」→ 措施 + 为什么有效；
- 「比较」→ 用表格或成对表述，先给维度再给结论。

## 第二步：逐问作答结构

每一问都按同一骨架展开，阅卷老师找的是**关键词**：

```markdown
### 第 X 问（Y 分）

**结论/判断**：（先给判断，不要铺垫）

**依据**：（教材术语 + 题干事实）

**措施**（写多条，每条一行）：
1. 措施 —— 解决什么问题
2. 措施 —— 解决什么问题

**代价/边界**：（该方案的局限，体现权衡意识）
```

> 「代价/边界」是拉开分差的地方。只写优点的答案通常只能拿到基础分。

## 高频专题与检查点

| 专题 | 常考问题 | 答题必须出现的要点 |
|---|---|---|
| 质量属性与 ATAM | 识别场景/敏感点/权衡点 | 刺激、环境、响应、响应度量四要素 |
| 架构风格选型 | 为什么选/不选某风格 | 数据流/调用返回/数据中心/虚拟机/独立构件 |
| 层次式架构 | 分层职责与依赖方向 | 表现/中间/数据访问/数据层的边界 |
| 云原生 | 改造路径与反模式 | 服务化、弹性、可观测、自动化 |
| SOA / 微服务 | 服务划分与治理 | 松耦合、粗粒度、无状态、可组合 |
| 安全架构 | 威胁 → 措施映射 | 纵深防御、身份、数据、审计、应急 |
| 可靠性 | 容错与检错设计 | MTTF/MTTR/可用度、冗余、降级 |
| 大数据 | Lambda/Kappa 选型 | 批处理层、速度层、服务层的权衡 |

## 常见失分原因

1. **只写概念不结合题干**：答案里没有出现题干中的系统名或场景。
2. **问题与措施混在一起**：一问要求「指出问题」，却写了整改方案。
3. **术语不规范**：用口语描述，而不是教材术语（如「分开」而非「解耦」）。
4. **漏答分问**：5 选 3 时看错题号，或漏掉某问的第二小问。
5. **没有权衡**：通篇只讲优点，看不出工程判断。
